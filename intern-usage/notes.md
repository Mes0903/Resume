# Mentor 履歷 Review 重點（2026-08-12）

## 結構與經歷

- 學生履歷若有 Summary，Education 應緊接在 Summary 後；有正式工作經歷後，可改成 Summary → Employment → Education。
- 若工作或研究經歷都發生在校內，可併入 Education 並列在對應學校之下，不必另開 Experience。
- 轉學等背景簡短交代即可；應凸顯目前最有價值的成果，避免舊學校的內容比現就讀學校更重。
- 選擇經歷時看實際內容，不要只因職稱正式就保留；本次因此保留系網管經歷，而未保留實質較接近助教工作的 Research Assistant 經歷。

## Bullet 與專案

- 一般 Experience／Project bullet 盡量接近完整一行：太短容易顯得內容不足，三、四行又不易閱讀；這是原則而非硬性限制。
- 技術 bullet 要有足夠的實作資訊，但不要堆疊到非該領域的 manager 難以理解，也不必硬塞 CI/CD 等不重要的內容。
- 不要只依 GitHub stars 篩選專案；能展示能力的小型或視覺化作品也值得放。Early-career 履歷可列約四個有代表性的專案。
- Section 可直接命名為 `Open Source Projects`，不必加上 `Selected`。
- 每個 project 都應有可驗證的連結，例如 GitHub、Demo、Video 或 URL；mentor 偏好在項目後使用標明類型的 link tag。

## Talks

- Talk 是 early-career 履歷的重要亮點，不應只壓成簡短的單行列表，也不必標示 `Speaker` 或 `Co-speaker`。
- 以 conference 名稱作為項目標題，內文註明議程軌與完整講題。
- 附上 Talk、Slides 或 Video 等可點擊連結。
- 「bullet 盡量一行」主要適用一般經歷與專案；Talk 可以為了完整呈現而寫得更長。

## Publications、Skills 與語言

- 原創技術寫作可放在 Publications 或 Articles；廣義的 publication 也能包含文章、教材、slides 與 talks。
- 品質與份量足夠的翻譯作品可以列入；未完成作品只有在已具展示價值時才放，並標示為 work in progress。
- Early-career 階段保留獨立 Skills section 沒問題；累積數年工作經驗後，應逐步讓技能自然呈現在工作與專案成果中。
- 語言能力應保守描述；日文寫 `Japanese (basic)`，不要寫 `basic conversational`，以免提高對方對實際溝通能力的預期。
- Header 不要顯示完整 raw URL；使用 `GitHub`、`LinkedIn`、`Website` 等標籤，並注意品牌名稱的正式拼法。

## 本次後續決定（不是 mentor 的明確要求）

- `English (working proficiency)` 是依實際能力採用的描述，不是 mentor 指定。
- Education 細項不列日期、學校日期使用 `Present`，以及不列預計畢業年月，都是後續版面決定。
- 連結緊接在對應項目後、不靠右對齊，是後續版面決定；mentor 的核心要求是連結清楚、可點擊並標明類型。
- 專案取捨及各 bullet 的確切措辭是後續討論結果；不要為了看似精確而加入 mentor 未要求、作品也無法直接支持的描述。
- 公開版本可移除電話與 Email；正式投遞時再依收件方需求決定是否加入。
